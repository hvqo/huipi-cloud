# 日常作业：班级布置与教师代收

该工作流复用已有的 Assignment、Submission、解析任务、Canonical、作答复核、GradeInput 和 GradeProposal。学生名单来自现有 Student 与 ClassEnrollment；它不建立学生登录，也不把姓名或学号当作认证凭据。

## 使用条件

1. 学校已有当前学期、学科、行政班、学生和有效班级归属。当前数据库管理员在「教师任教关系」登记教师、学期、学科与班级；登记和撤销分别记录操作者及时间。该关系不授予教师其他班级、考试或成绩权限。管理员需先在账号管理中核对用户编号。
2. 教师创建作业，添加题目、标准答案及评分项，发布后选择自己有任教关系的班级和截止时间。应交名单在布置时按上海业务日期和当时有效的班级归属形成快照，之后转班不会静默改变已有名单。首版一次布置最多 20 班、2000 名学生；布置后暂不支持修改班级及快照。
3. 看板按当前教师可访问的班级显示应交、已交、未交和迟交。未交不是零分。代收支持 PDF、PNG、JPEG，沿用上传大小配置（默认 20 MiB），使用有界临时文件；同一 request_id 可重放，同一学生重交产生新的 Submission 和递增版本，历史版本只读。
4. 文本评分需启动已有的普通作业解析 Worker（见 `docs/development/mineru.md`）。解析完成后，教师在当前提交页点击「准备作答核对」，复用现有标准化和题目对齐；教师核对来源并保存作答确认后，才能请求文本评分建议。
5. 图片评分可在当前提交的题目下展开「图片作答批改」，查看 PDF、PNG 或 JPEG 原页，框选一至八个区域并确认，再请求评分。它不要求 OCR 先成功，也不将图片内容伪装为文本 Quote。可选择附带已经通过原有作答核对链路确认的文本；无确认文本时不能打开此选项。服务器校验原件 SHA、渲染页和裁剪摘要，以相同的视觉评分协议约束 Rubric、分值及图像证据；教师可接受、修订、拒绝或要求人工判读。
6. 图片评分使用既有 DeepSeek Flash 适配器，须明确启用 `GRADING_VISUAL_ENABLED` 和已有远程调用、外部传输授权，且只允许传输已获授权的学生材料。模型候选须教师复核，不自动发布成绩。模型弃权、服务失败或未复核均不表示零分；未配置模型时不会用测试 Provider 替代。

## 权限与边界

服务端同时检查作业成员关系和对应的有效任教关系，旧作业管理员身份不会单独赋予新班级提交访问权。班级授权撤销后，新请求被拒绝。旧 Submission 列表和 Copilot 不返回由本工作流管理的提交，原有未关联班级的旧提交行为保持不变。每次提交和批改均从服务端解析当前学生及版本，不接受客户端指定学生身份来替代可信名单。

当前班级复核数表示当前提交已存在的教师接受或修订记录，并非对所有来源有效性的持续证明；教师应进入该题核查。标准化、对齐或评分期间若当前提交更换，旧产物作为历史保留，接口重新校验后拒绝将其作为新版本结果。S3 与数据库不是同一事务：结果未知时保留对象并用原请求号核查或重试；孤立对象需由受控运维对账。

图片选区、视觉输入和教师复核均绑定服务端实际解析出的当前 HomeworkAttempt。新选区会使此前的图片复核不再计入看板；文字复核仍按原有确认来源处理。教师重交后历史选区和评分仍可审计，但不能作为新提交的结果。每次选区最多产生一个评分任务，失败时教师须重新确认区域后显式发起；不会自动换模型、重复请求或修补模型证据。网络中断后请求仍显示处理中时，应先刷新核查；长时间未结束的记录需由受控运维排查，不能据此认定有分数。

## 已知限制

- 无学生本人登录、在线答题、按班二次增补名单或自动提醒；无真实学生授权时不会提供模拟学生提交入口。
- 图片/PDF 原件受现有上传上限约束（默认 20 MiB）；本入口 PDF 最多 50 页，每题最多 8 个选区，每个裁剪图最多 1 MiB；不支持跨不同提交拼接选区。图片评分的视觉充分性仍须教师核验，合成样例通过不代表真实教学评分准确率。
- 教师可添加多个题目；网页首版每题填写一个评分项。原有 API 支持更完整的 Rubric，正式发布前仍需核对。
- 仪表盘不自动计算正式成绩；重交后的旧评分不会变成新版本的成绩。
- 管理员任教关系列表每类最多显示前 100 项且明确提示截断；超出时使用受控管理接口处理。教师仅能为本人已登记的班级布置。

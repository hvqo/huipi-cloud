# 考试正式成绩管理

`/final-results` 面向具有相应授权的教师和考务人员。先逐人确认到考、缺考或待核验；没有答卷不会自动成为缺考，也不会自动得到零分。考务负责人可以核对当前批改状态，生成待审批版本，查看其快照，再分别批准和发布。教师只能查看和导出自己被明确授权的班级。

## 成绩来源与版本

生成版本时，服务端锁定场次和当前冻结名单。到考学生必须拥有当前完整、身份可信的答卷及真实卷版，全部题目均须有当前有效的教师 accepted/revised 复核，或教师明确确认的 OMR 客观题决定；模型候选本身不计分。缺考必须由人员明确记录，且不能已有该学生的已确认答卷。缺考结果不具有总分。待核验、缺评、弃权、退役卷版或失效来源均阻止生成。

待审批版本包含每个参试者的名单、到考决定、答卷版本与逐题复核或 OMR 记录的真实引用。版本、明细和到考历史不可原位删除或修改。审批及发布前重新读取并验证当前名单、答卷、权限与逐题来源，任何变化都拒绝继续发布；负责人应作废该待审批版本并重新生成。版本操作使用请求编号、版本号和同事务审计；提交结果未知可使用相同请求重放。

发布后的版本是历史事实，不因后续修改而原位改变。发现错误时先在既有评分或 OMR 工作区进行受控教师更正，之后生成、审批和发布后继版本。旧版可按班级授权查询。系统不根据新数据自动改写旧版，也不自动发布。

## 授权与部署

普通读取和导出继续使用现有 `ExamResultClassAccess` 班级收窄。每个班级的读取动作必须由同一条当前 Grant 覆盖；导出还要求该班级的导出授权。JWT 角色、旧管理员或作业成员身份不能绕过这些限制。

到考确认及生成版本要求 `exam.result.manage`；审批要求 `exam.result.approve`；发布要求 `exam.result.publish`。执行者还必须有覆盖当前名单全部班级的明确成绩访问，且每个班级的 Grant 必须同时包含所需成绩动作与成绩读取动作，不能把不完整 Grant 拼接。普通教师不自动获得成绩管理能力。

迁移提供固定的 `exam_result_manager` 与仅用于受控授权部署的 `exam_result_deployer` 角色。部署操作员由现有安全管理员在批准后通过 `python -m huipi_cloud.modules.exam_results.final_deployment --actor-user-id ... --target-user-id ... --request-id ... --approval-ref ... --confirm-deployment-operation` 显式启用；再通过现有安全委派及 `exam_results grant-class` 为负责人指定真实场次与各班级范围。它不是公共注册或教师自助提权入口。生产迁移需由部署人员执行，本功能不自动升级数据库。

## 统计、导出与限制

统计只使用所查看的已发布版本和当前获授权的班级；不同实际 PaperVersion 和满分分别计算平均、最高、最低、分数段及各题得分率。班级完成率定义为「到考且完成全部复核人数 / 名单人数」；缺考不计入平均分，发布版本的缺评数为零。若仍有缺评则无法生成可发布版本。

Excel 是受保护、重新鉴权的正式版本导出，包含到考状态、逐题分数和版本摘要；文字按字符串写入以避免公式执行，学号保留前导零，缺考分数留空。单场次当前最多 100 人、2,000 个题目单元，整次构建最多 60 秒，适用于小规模 MVP，不代表全校大规模性能验收。当前不支持选做规则、双评仲裁、正式成绩撤回、学生端发布或排名；如需调整已发布成绩，使用后继版本更正。

# 教师考试配置工作台

## 范围

`/exams` 与 `/exams/sessions/{id}` 提供真实 OIDC/JWT 下的考试配置页面。
从既有可信组织、学生和已锁定试卷开始，在网页创建考试与科目场次、绑定共享 A/B 卷、预览参试班级、保存并冻结名单，
随后进入原扫描、分卷、身份确认、解析、批改及成绩预览入口。不会创建第二套扫描、解析、评分或成绩模型。

本模块没有数据库迁移。写操作直接调用原 `exams.service` / `exam_rosters.service`，保留原 request_id、revision、
行锁、数据库触发器、审计事务及 COMMIT 未知恢复。唯一迁移Head仍为 `b15a60c4f015`。

## 操作员准备

1. 部署已配置 OIDC；Token 在原内存会话中管理，无匿名模式、URL Token或客户端角色授权。
2. 学年、学期、学科、行政班、可信学生与班级归属已通过组织/导入模块建立。
3. 至少一份锁定 PaperVersion；A/B 场次需要两份不同卷版，不能以题号或班级克隆推断卷别。
4. 操作员具有明确的当前 Grant。新建考试需要安装级 `exam.event.create`；考试管理使用安装/Event Scope；
   场次管理使用安装/Event/Session Scope。网页只展示服务端计算的操作能力，不把 capability 当作执行凭证。

配置模块不创建或提升用户角色，不给创建人自动新增 Grant，也不自动授予成绩班级权限。
仅有创建权限而没有后续读取/管理权限的主体，创建后需由考务负责人另行授权。
首次身份注册、Grant委派、组织基础字典维护仍使用受控工具；试卷快照创建/编辑/锁定已可进入[试卷管理工作台](paper-workbench.md)。不提供排版编辑器。

## 网页操作

### 考试与科目场次

- 在「考试配置」选择已授权考试，或新建考试并选择真实学年及其学期。
- 新建科目场次，选择真实学科，填写开始/结束时间和单卷或 A/B 双卷策略。
- 页面明确使用**北京时间 Asia/Shanghai**；提交显式 `+08:00`，不依赖浏览器所在时区。
- 场次属于一个考试，多班共用同一场次。另一个场次可以复用同一锁定卷版。

### 共享用卷

选择已锁定且具有 `paper.use` 的卷版，明确绑定 A/B。
显示版本、题数、Decimal总分、Rubric完整性与内容摘要一致状态；不展示试题正文、标准答案或Rubric说明。
`paper.use` 不是 `paper.read`。只拥有场次管理不能随意选取其他卷版，也不能读取其答案。

草稿可受控撤销关联，历史行不删除。配置完整后标记「用卷准备就绪」。
就绪不代表名单已冻结、学生到考、扫描或批改完成。锁卷和退役竞态继续由原Service与数据库检查。

### 名单

1. 名单预览需要**同一Grant**的 `exam.roster.manage` + `exam.roster.read`，以及独立安装级 `organization.read`。
   后者允许浏览学校组织材料，不自动从Session权限推导；无此权限可读取已经授权的现有名单，但不能浏览全校班级学生。
2. 选择多个真实行政班，服务端以场次开始的学校本地业务日期查询历史 `ClassEnrollment` 半开区间。
   同名学生由真实Student ID和学号区别，不按姓名合并。
3. 核对学生、考号、卷别。首次不自动生成考号或猜A卷；「按当前顺序编排考号」及统一卷别均是教师显式操作。
   更正预览尽可能复用当前冻结名单的考号和卷别，但提交及冻结仍重新核验来源。
4. 停用学生显示异常；重复考号、缺考号或空名单不能冻结。卷别允许保持待核验，后续身份确认必须继续检查实际用卷。
5. 保存完整名单草稿。网页区分本地未保存修改与已保存草稿，存在修改时不能直接冻结旧草稿。
6. 冻结需要单独 `exam.roster.freeze`。冻结内容只读；更正需要同一Grant的 `manage+correct`，
   创建后继完整快照，冻结前旧版仍current，冻结后原子切换。旧身份、考号及快照不覆盖。

读取名单需要单独 `exam.roster.read`；有配置或扫描权限不等于允许读取所有学生。
没有扫描不推断缺考，没有作答不生成零分。

### 衔接与成绩授权

「扫描接收与页面预览」携带明确场次筛选，旧扫描列表在真实授权过滤内按ID查询；无权时返回空列表，
不会静默改为另一场考试。人工分卷、身份确认、解析与批改继续使用原答卷工作区。

整卷成绩预览与Excel入口沿用[独立班级限制](exam-results-preview.md)，配置权限不产生 `ExamResultClassAccess`。
无成绩班级授权时清楚显示无可访问场次，不能因为完成考试配置而获得全场次成绩。

## HTTP与安全边界

固定前缀 `/api/v1/exam-configuration`，19个操作、17个路径，进入原固定HTTP权限目录和OpenAPI：

- `GET /options`、`/events`、`/sessions`、`/papers`：当前授权过滤的有界选项与列表。
- `GET /events/{id}`、`/sessions/{id}`：真实父级Scope；展示名称、日期和配置状态。
- `POST /events`、`/events/{id}/sessions`：创建考试、场次。
- `POST /events/{id}/state`、`/sessions/{id}/state`：复用原合法生命周期变更；本轮Vue主要开放场次ready。
- `POST /sessions/{id}/papers`、`/papers/revoke`：绑定/撤销；场次manage+bind必须同一Grant，另需目标paper.use。
- `POST /sessions/{id}/roster-preview`：只读预览，无业务写入，不把客户端日期或姓名当作事实。
- `GET/POST /sessions/{id}/rosters`：版本历史/创建初始草稿。
- `GET /rosters/{id}`、`POST /entries`、`/freeze`、`/corrections`：读取、完整替换草稿、冻结及新版本更正。
  这些子路径的名单ID先经数据库解析到真实场次，不能拼接另一场次权限。

下游扫描仅增加可选 `GET /scan-sessions?exam_session_id=...` 筛选；原默认行为不变。
旧OpenAPI Schema完全保留，不放开旧Assignment/Submission/Worker对考试资源的可见性。
原始Core查询只在固定可信服务内；不接收SQL、表名、对象Key、任意URL、actor或自由授权JSON。

## 并发、故障与上限

- 写入和重放都按原Service重新检查当前User/Grant。客户端role、is_admin或Membership不授权。
- request_id和完整原始正文在本页内存保留。结果未知时锁定编辑，只能重试原请求；错误或撤权不会伪造成功。
  新建对话框内也可直接重试，不要求关闭弹窗。页面刷新/关闭不提供跨会话请求恢复，应先查询现有版本。
- 新增POST入口流式累计请求体，最多1MiB、读取10秒；操作120秒。数据库单句/锁等待继续依原事务策略。
- 列表每页20；组织选项每页100项，网页最多读取1000项并明确truncated；名单预览/读取每页100、至多2000人、一次至多20班。
- 源组织可能在预览期间改变；预览不是永久许可，保存和冻结重验可信来源。无法冻结时保持草稿，不推断成绩。
- 名单大批量写入仍使用主线原实现；未夹带Draft性能优化，不承诺全校规模吞吐。

完整操作、负向与浏览器证据见[验收记录](../evaluation/exam-configuration-workbench.md)。

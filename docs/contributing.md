# 文档维护规范

1. README 只维护稳定的项目定位、当前用户能力、主要架构、快速启动和文档入口。
2. 新功能优先更新对应模块文档；只有影响用户使用方式或整体架构时才修改 README。
3. 阶段计划和进度放在 `docs/roadmap.md`，不追加到 README。
4. 模型实验、评测指标和失败案例放在 `docs/evaluation/`，不把单次结果写入项目首页。
5. 环境安装、Worker、CLI 和开发操作放在 `docs/development/`；技术复盘放在对应的架构或专题文档。
6. 公开文档不得包含访问凭据、真实学生作业或未经授权的个人资料。
7. 新增或移动 Markdown 文件后，检查所有相对链接仍可解析；提交前运行 `git diff --check`。

文档链接采用仓库内相对路径。代码或 API 行为变化时，应同时检查操作指南的示例是否仍可执行。

# 架构与模块边界

慧批云端采用 src 布局的模块化单体。当前应用仅提供启动配置、基础日志和健康检查，不连接数据库、文件存储或模型服务。

## 分层职责

- api/v1/：HTTP 路由、请求与响应边界；调用应用模块，不承载领域规则。
- core/：应用级配置和跨模块基础能力；不依赖具体业务模块。
- modules/：按教学领域组织业务能力。assignments 管理作业流程，parsing 负责文档解析，grading 负责评分与批改，copilot 面向教师助手，review 面向教师复核。
- infrastructure/：数据库、文件存储、大模型、消息和检索等技术适配器。业务模块通过明确的调用边界使用适配器，不直接耦合供应商细节。
- workers/：后续承载异步任务入口；当前不包含队列或后台执行代码。
- tests/：unit/ 放置快速的模块级测试；integration/ 用于未来验证多个模块的协作。

## 依赖方向

请求由 API 层进入应用模块，模块通过 infrastructure 中的适配器接触外部技术。基础配置与日志可被各层使用；infrastructure 不负责教学领域规则。模块之间保持清晰的领域边界，避免相互导入实现细节。

目录中的空包仅用于固定后续模块位置，不代表相应业务能力已经实现。

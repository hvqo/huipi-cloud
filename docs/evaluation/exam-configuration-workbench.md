## 真实 PostgreSQL / 私有 S3

使用本任务独立 PostgreSQL 16 容器和私有测试 S3；没有连接或迁移用户开发数据库。
测试保留 SQL 外键、不可变触发器、原 Service 审计事务及实际签名 JWT。

新增 `tests/integration/test_exam_configuration.py` 七项全部通过，最终运行 49.49 秒，覆盖：

1. 真实 HTTP 创建、相同 request_id 重放与正文冲突、A/B 用卷、两班日期快照、未知卷别、冻结与后继 current 切换。
2. 无 Token、无考试授权、伪造客户端角色、跨场次和未授权列表。
3. 错误卷版 UUID、过期 revision、非法班级拒绝且无业务写入。
4. Session Scope 列表及精确扫描场次筛选、撤权后的请求重放拒绝。
5. 跨场次卷别、重复考号、两个并发冻结请求只有一个成功，数据库 current 唯一。
6. 审计失败整体回滚、数据库不可用、无 Content-Length 的超限请求体拒绝。
7. paper.use 元数据无标准答案、草稿/退役卷拒绝新绑定、历史保留及旧接口隔离。

这 5 项重新执行全部通过（46.19 秒）。**这不是一次命令 88 项全绿的记录**。
新增七项包含在上述 88 项中，不能重复累计。
没有修改任何已应用迁移；独立库往返、Alembic check 与存在业务事实时拒绝破坏性降级仍有效。

最终浏览器运行：Python 驱动 1 项通过（44.76 秒），内部 Chromium **4 个场景通过**（34.4 秒）：

- 既有 Unicode 作答证据、幂等/冲突及只读工作流。
- 真实图片预览及旧作业创建。
- 考试混班 PDF 接收、页面预览与原件校验。
- 新考试配置：创建考试 → 创建 A/B 场次 → 选择两个锁定卷版 → 用卷就绪 → 两班四人名单
  （两人同名）→ 显式编考号和 A/B 卷 → 保存/冻结 → 新版本更正考号并再次冻结 →
  打开精确场次扫描入口、原分卷/批改入口、成绩预览入口。

第四项还模拟服务器已经提交、浏览器未收到响应，验证使用原 request_id 和原正文重试。

未授予成绩班级权限的配置操作员仍得到无可访问成绩场次，不因配置成功而扩权。

仍依赖受控工具的内容：首次身份/Grant 部署、组织与学生可信导入、试卷快照创建/编辑/锁定、成绩班级授权。
本轮不提供排版编辑器、全校组织管理界面、正式成绩审批/发布、自动缺考判定或自动零分。
生命周期 HTTP 保留原规则，Vue 主要开放场次 ready；更复杂撤场/改期仍由受控操作处理。
页面关闭不保存未知结果的重试正文，应先查询业务状态；大名单性能继续沿用主线实现。
配置页能力与安全控制不代表已完成真实学校业务容量和教师易用性验收。
